# 数据库说明

MySQL 8.0 / utf8mb4 / 库名 `oa_system`。所有表都有 `id` 主键与 `created_at`、`updated_at`，业务表另有 `deleted_at` 做逻辑删除（MyBatis-Plus `@TableLogic`），查询默认过滤已删除行。

## 一、初始化

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| 一键建库（推荐） | `scripts/init-db.ps1 -Password 你的密码` | 建库 + 导入 `sql-init-20261024.sql`（基线：结构 + 演示数据） |
| 强制重建 | `scripts/init-db.ps1 -Password 你的密码 -Force` | 库已存在时不再询问，直接 DROP 后重建 |
| 手工导入 | `mysql -uroot -p oa_system < sql-init-20261024.sql` | 需要自己先 `CREATE DATABASE` |

`sql-init-20261024.sql` 是当前完整基线，包含 13 个流程定义、5 个通知模板、6 个费用类别、119 条菜单权限、9 个角色及其授权、12 个演示账号。

**升级旧库**：`sql-migration-*.sql` 是历次增量脚本，按文件名里的日期顺序执行；基线已包含全部增量，新环境不需要再跑。执行前先备份（`mysqldump --single-transaction`）。

## 二、表分组

### 1. 组织与权限（10 张）

| 表 | 用途 |
| --- | --- |
| `users` | 账号主表。含组织、职位、状态、`salary`（月薪，仅 HR/财务/总经理/管理员可见）、紧急联系人、银行卡、`must_change_password` |
| `roles` | 角色。`data_scope` 1 全公司 / 2 本部门 / 3 本部门及下级 / 4 仅本人 / 5 本人负责的项目 |
| `user_roles` | 用户与角色多对多 |
| `menus` | 菜单与权限码。`menu_type` 1 目录 / 2 菜单 / 3 按钮；`menu_code` 是接口 `@RequirePermission` 判定的权限码 |
| `role_permissions` | 角色与菜单（权限码）多对多 |
| `user_permissions` | 用户级临时授权（如「任务中心访问」`task:access`），`source` 1 管理员授予 / 2 派发任务自动开通 |
| `organizations` | 部门树，`parent_id` 自关联，`leader_id` 是部门主管（审批人解析 type=3 用） |
| `positions` / `titles` | 职位、职称字典 |
| `page_controls` | 前端控件级权限配置（预留，当前未使用） |

### 2. 流程引擎（5 张 + 1 张委托）

| 表 | 用途 |
| --- | --- |
| `flow_definitions` | 流程定义。`form_config` 是动态表单 JSON；`use_scope` 0 全员 / 1 指定部门 / 2 指定角色 + `use_scope_ids` |
| `flow_steps` | 审批步骤。`approver_type` 1 指定用户 / 2 指定角色 / 3 部门主管 / 4 指定职位 / 5 发起人自选 / 6 指定部门先到先得；`sign_type` 2 会签、3 比例会签 + `sign_ratio` |
| `flow_step_transitions` | 步骤流转线。`condition_expr` 支持 `amount >= 1500`、`reason contains '加急'`，`is_default=1` 是默认分支 |
| `flow_instances` | 流程实例。`status` 0 草稿 / 1 审批中 / 2 已完成 / 3 已驳回 / 4 已撤回；`current_auditor_id` 为空表示池式待认领 |
| `flow_approvals` | 审批轨迹。`action` 1 通过 / 2 驳回 / 3 转交 / 4 撤回 / 5 催办；`sign_status=1` 表示「提交申请」写入的节点，统计已办时要排除 |
| `flow_delegates` | 审批委托（代理人、委托时间段、原因） |

> 流程引擎只按 `flow_step_transitions` 前进，不按 `sort_order`。新增步骤必须补流转线，否则发布校验会拦下。

### 3. 出勤（7 张）

| 表 | 用途 |
| --- | --- |
| `attendance_records` | 每日打卡。`status` 0 正常 1/7 迟到 2/9 早退 3 缺勤 5 出差 等 |
| `attendance_makeup` | 补签申请。`current_stage` 1 主管初审 / 2 人事终审；每月上限 3 次 |
| `attendance_appeals` | 打卡异常申诉（`approver_id` 是审核人） |
| `attendance_outing` | 外出打卡记录 |
| `shift_templates` / `shift_schedules` | 班次模板与排班 |
| `holidays` | 法定节假日与调休日（影响应出勤天数） |

### 4. 工作日志（6 张）

| 表 | 用途 |
| --- | --- |
| `worklogs` | 日志主表，`status` 0 草稿 / 1 已提交 |
| `worklog_comments` | 日志评论 |
| `worklog_categories` | 日报 / 周报 / 月报等类别 |
| `worklog_supplement_approvals` | 超 30 天补写申请（**该表没有 `deleted_at`**，写 SQL 时别加） |
| `worklog_view_permissions` | 日志查看授权（把某篇日志临时开放给指定人） |
| `attachments` | 通用附件表，日志/流程/申诉共用，靠 `biz_type` + `biz_id` 关联 |

### 5. 任务与项目（5 张）

| 表 | 用途 |
| --- | --- |
| `projects` | 项目。`status` 0 未启动 / 1 进行中 / 2 已暂停 / 3 已完成 / 4 已取消；`progress` 由任务进度自动汇总 |
| `project_members` | 项目成员，`role` 1 项目经理 / 2 成员 |
| `tasks` | 任务。`status` 0 待接受 / 1 待分配 / 2 进行中 / 3 待验收 / 4 已完成 / 5 已撤销 / 6 已驳回 |
| `task_members` | 任务参与人 |
| `task_comments` / `task_operation_logs` | 任务评论与操作留痕 |

### 6. 公告、通知与系统（10 张）

| 表 | 用途 |
| --- | --- |
| `announcements` / `announcement_categories` / `announcement_category_roles` | 公告、公告分类、分类可见角色 |
| `announcement_reads` | 公告已读记录（用于已读统计） |
| `notification_records` | 站内通知。`push_status` 0 未推送 / 1 成功 / 2 失败 + `push_channel`、`push_fail_reason` |
| `notification_templates` | 通知模板，标题/内容里用 `{title}` 这类占位符 |
| `user_notification_preferences` | 通知偏好 |
| `system_params` | 系统参数（签到地理校验开关、坐标、半径、周末是否计入出勤） |
| `nav_images` | 导航图片素材 |
| `system_config` | 兼容旧配置项 |

### 7. 财务、招聘、人事与其他

| 表 | 用途 |
| --- | --- |
| `payment_records` | 付款单。`category_id`/`category_name` 记录费用类别，`status` 0 待付款 / 1 已付款 / 2 已作废 |

| `user_third_party_bindings` | 企业微信/钉钉账号绑定（只存 external_id，不存第三方令牌） |
| `login_logs` / `operation_logs` / `exception_logs` / `online_users` | 登录日志、操作审计、异常日志、在线用户 |

| `tool_downloads` | 工具下载计数 |

## 三、常用运维 SQL

```sql
-- 各表行数概览
SELECT TABLE_NAME, TABLE_ROWS FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'oa_system' ORDER BY TABLE_ROWS DESC;

-- 某个角色的全部权限码
SELECT m.menu_code FROM role_permissions rp
JOIN menus m ON m.id = rp.menu_id
JOIN roles r ON r.id = rp.role_id
WHERE r.role_code = 'manager' AND m.deleted_at IS NULL ORDER BY m.id;

-- 当前待付款单据
SELECT instance_no, title FROM flow_instances WHERE status = 2
AND definition_id IN (SELECT id FROM flow_definitions WHERE need_payment = 1)
AND id NOT IN (SELECT instance_id FROM payment_records WHERE status = 1 AND deleted_at IS NULL);
```

## 四、一致性自检脚本

上面这些 SQL 是手工排查用，日常验收跑脚本更快：24 条跨表规则（逾期标记与状态是否一致、项目进度与任务是否对得上、停用账号是否还挂着待办、通知是否指向已删除的流程/任务、补签与申诉是否缺审批人等），只读、不改数据。

```powershell
.\scripts\check-db-invariants.ps1                       # 默认 root/861202，库 oa_system
.\scripts\check-db-invariants.ps1 -Database oa_test -Password 你的密码
```

输出是一张「规则 / 含义 / 违例数」的表：全部 0 打 `0 OK` 并退出码 0；有违例标红并退出码 1，可以直接接进部署前检查。连不上库退出码 2。

## 五、注意事项

1. **逻辑删除**：统计「总数」时如果用 `COUNT(*)` 会连软删行一起算，和接口返回对不上；要比对就用 `deleted_at IS NULL`。
2. **时区**：JDBC URL 里必须带 `serverTimezone=Asia/Shanghai`，否则打卡时间会错 8 小时。
3. **附件物理文件**：数据库只存路径，真实文件在 `oa.upload-dir`（默认项目根 `uploads`），备份时两者要一致。
4. **流程实例不要直接删**：删实例要同时清 `flow_approvals` 与 `notification_records`（`biz_type='flow_instance'`），否则通知会变成死链。
