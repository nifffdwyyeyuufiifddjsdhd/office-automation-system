# 交付核对表

对照 `.backup/docs-dump/OA办公系统-开发执行摘要.txt` 的硬性规范与功能清单，逐条说明落地情况。
图例：✅ 已实现并验证 · 🟡 已实现但与文档写法不同（附原因） · ⛔ 本机条件不满足（附替代方案）

## 一、接口与响应规范

| 文档要求 | 状态 | 说明 |
| --- | --- | --- |
| 接口前缀 `/api/v1/` | 🟡 | 实际统一用 `/api`。302 个后端接口与前端 297 个调用函数都已按 `/api` 落地，改造收益为零、回归风险大；版本化建议留给下一次大版本，届时用 Nginx 加一层 `/api/v1` → `/api` 即可，不需要改代码 |
| 统一响应 `{code,message,data,timestamp}` | ✅ | `common/Result.java` 重写，四个工厂方法都带毫秒时间戳；实测 `/api/public/announcements` 返回含 `timestamp` |
| 分页参数 `page/page_size`，响应 `{list,total,page,page_size,total_pages}` | 🟡 | 实际沿用 MyBatis-Plus 风格 `pageNum/pageSize` + `{records,total,pageNum,pageSize}`，前端所有表格都依赖这套字段；`pageSize` 上限 500、`pageNum<1` 归一到 1 |
| 双层错误码（HTTP + 4 位业务码） | 🟡 | 新建 `common/ErrorCodes.java`（1001-1099 用户、2001-2099 流程、3001 出勤、4001-4002 任务），登录失败已是 `1001`；其余业务失败仍是 HTTP 200 + `code=500` + 中文文案（项目既有约定，前端按这个判断），未把 300+ 处 `Result.error(msg)` 全改成四位码 |
| 401 / 403 / 429 语义 | ✅ | 未登录 401、无权限 403、限流 429（附 `Retry-After: 60`） |

## 二、安全

| 文档要求 | 状态 | 说明 |
| --- | --- | --- |
| bcrypt(salt=10) | ✅ | `config/SecurityConfig.java` 显式 `new BCryptPasswordEncoder(10)` |
| JWT 鉴权 + 密钥可配 | ✅ | `jwt.secret` / `jwt.expire-hours` 走环境变量，默认密钥启动时打告警 |
| CSRF | ✅ | 无状态 JWT，前端不带 Cookie，Spring Security 已关 CSRF（Token 机制天然免疫） |
| XSS 白名单 | ✅ | 前端 `src/utils/safeHtml.ts`：DOMParser 解析后按标签白名单重建，丢弃 `script/style/iframe/object/form`、所有 `on*` 事件属性、`javascript:`/`vbscript:`/非图片 `data:` 协议，`style` 里含 `expression()` 直接清空。公告管理、公开公告页、登录页公告弹窗三处 `v-html` 全部接上 |
| 上传白名单 + 大小限制 | ✅ | 通用单文件 50MB（`multipart` 配置）、工作日志附件 20MB（`WorklogController` 单独校验）；扩展名白名单 + 魔数校验（`typeMatchesExt`），Nginx 侧 `client_max_body_size 60m` |
| CSV/Excel 公式注入 | ✅ | `utilt/ExcelSafe.java` 覆盖 7 个导出接口，落在 `=`、`+`、`-`、`@`、Tab、CR 开头的单元格加前缀单引号；单测 `ExcelSafeTest` |
| 敏感字段脱敏 | ✅ | `service/SensitiveDataService.java`：手机号 `180****0000`、邮箱 `h***@domain`，本人看自己保持明文；薪资字段 `user:salary:view` 控制，无权者一律返回 null（含本人） |
| CORS 白名单 | ✅ | `cors.allowed-origins` 可配，默认只放本机 5173/5174；实测陌生 Origin 返回 403 且不带 `Access-Control-Allow-Origin` |
| 操作审计 | ✅ | `interceptor/AuditLogInterceptor.java` 统一拦截所有 POST/PUT/PATCH/DELETE 写操作并落 `operation_logs`（模块/动作/接口/IP/耗时/成功与否），业务层已手写的详细日志通过 `AuditLogService.RECORDED_ATTR` 标记去重；系统管理 → 操作日志可查，请求参数里的手机号会脱敏 |
| 异常日志 | ✅ | `exception/GlobalExceptionHandler.java` 把未捕获异常自动写 `exception_logs`（类型/消息/堆栈/URL/IP/操作人），系统管理 → 异常日志可查看并标记处理；业务提示（中文短句）不落库，避免刷满 |
| 报错信息不泄露库结构 | ✅ | 数据库异常统一改成「数据查询失败，请稍后重试」，非法日期/数字按 400「参数格式不正确：日期或数字格式有误」，原始 SQL 片段只留在服务端与 `exception_logs` |
| 通知模板可维护 | ✅ | `service/NotificationTemplateService.java` + `utilt/TemplateRenderer.java`：待办到达（flow_arrive）、审批结果（flow_result）、任务指派（task_assign）、缺勤提醒（attendance_abnormal）四类通知都走 `notification_templates`，模板停用或缺变量时回退到代码兜底文案；系统管理 → 通知模板可改文案 |

## 三、基础设施

| 文档要求 | 状态 | 说明 |
| --- | --- | --- |
| Redis 令牌桶限流 | 🟡 | 本机离线仓库没有 `spring-boot-starter-data-redis`，改为 `config/RateLimitInterceptor.java` 进程内滑动窗口：登录类 20 次/分、其它 600 次/分，按 `X-Forwarded-For` 首段取真实 IP。**多实例部署必须换 Redis 实现**，单机/小内网够用 |
| Swagger / OpenAPI | ⛔ | 离线仓库同样缺 `springdoc` 依赖。替代方案：接口本身就是唯一事实来源，按 `controller/*.java` 的 `@RequestMapping` + `@RequirePermission` 自查；[docs/接口对账.md](接口对账.md) 给出后端 302 个路径与前端 297 个封装的差集。原生成的两份接口文档已按用户要求移除；扫描脚本 `scripts/gen-api-docs.py` 仍保留（`scripts/check-api-coverage.py` 复用它解析源码），需要时可重新生成。 |
| 三套环境（dev/test/prod） | 🟡 | `application.yml`（公共，全部走 `${ENV:默认值}`）+ `application-dev.yml` + `application-prod.yml`（生产必填项故意不给默认值，漏填直接启动失败）；test 环境暂用 dev 配置 + 独立库名 |
| 环境变量模板 | ✅ | `deploy/env.prod.example`（后端）、`OfficeAutomationSystemWeb/.env.example`（前端） |
| 迁移可回滚 | 🟡 | 提供完整基线 `sql-init-20261024.sql`（可随时重建）+ 26 个按日期排序的增量脚本；没有写与每个增量对应的 down 脚本，回滚方式是「备份恢复」或「重建基线」 |
| 单测（核心逻辑覆盖 ≥70%） | 🟡 | 现有 40 个单测 / 11 个测试类（`ExcelSafeTest` 2、`JwtUtilTest` 2、`SensitiveDataServiceTest` 5、`RateLimitInterceptorTest` 3、`ExpenseCategoryMatcherTest` 4、`FlowFormAmountReaderTest` 5、`TemplateRendererTest` 5、`PasswordPolicyTest` 6、`ResultTest` 5、`ErrorCodesTest` 3，外加 1 个 Spring 上下文冒烟），全部通过；未接入 JaCoCo（离线仓库无 `org.jacoco`），所以没有覆盖率数字，只报用例数 |

## 四、功能清单

| 文档要求 | 状态 | 落地位置 |
| --- | --- | --- |
| 会签三种规则 | ✅ | `flow_steps.sign_type` 2 全部会签 / 3 比例会签（`sign_ratio` 达到百分比即通过），1 或签；`FlowInstanceController.approveCountersign` 按实例+步骤+人去重计数，未达标返回进度提示，不锁 `current_auditor_id` |
| 批量通过不支持驳回 | ✅ | `/instances/batch-approve` 只做通过，且限制「同一流程 + 同一会签步骤」，会签步骤直接拒绝批量 |
| 驳回原因 ≥5 字 | ✅ | `FlowInstanceController.java:450` 「驳回原因必填且至少5个字」，上限 500 字 |
| 退回任意步骤 + 断点续审 | ✅ | `/instances/{id}/returnable-steps` + 驳回指定 `targetStepId`，重新提交后从被退回的步骤继续 |
| 审批人停用可转交 | ✅ | `/instances/{id}/transfer`（同一人同一事由最多 3 次）+ 离职交接 `/users/{id}/handover`（待办、在批流程、未结任务一并转出） |
| 看板拖拽 + 状态机校验 | ✅ | `TaskController./{id}/move`（`@Transactional`），按目标列分派认领/接受/提交/验收/撤销，非法流转返回 400 |
| 归档超 30 天单独入口 | ✅ | `TaskArchiveScheduler` 每日 02:30 归档；`/tasks/archive`、`/tasks/restore`、`/tasks/unarchive` 与前端「已归档」范围切换 |
| 日志附件 1 个 20MB、禁可执行 | ✅ | `WorklogController.uploadAttachment` 20MB + 扩展名白名单 + 魔数校验 |
| 日志补写最近 30 天 | ✅ | 超 30 天必须走 `worklog_supplement_approvals` 审批（部门主管审、管理员兜底），通过后开放 7 天 |
| 公告已读统计 | ✅ | `announcement_reads` 表 + `read_count`（去重人数），列表与详情都返回 |
| 补签每月 3 次 | ✅ | `AttendanceServiceImpl.java:45` 月度上限校验，超限提示「该日期的补签申请已达3次上限」 |
| 员工侧自助能力 | ✅ | 我的统计、我的补签/申诉/外出、第三方绑定、修改密码、通知偏好 |
| 访客角色（可选） | ✅ | `roles` 里 `guest`（默认停用）+ 免登录接口 `/api/public/announcements`（白名单）+ 登录页「公开公告」入口 |
